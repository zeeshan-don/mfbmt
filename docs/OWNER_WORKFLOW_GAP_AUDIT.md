## Focused code correction in this working copy

Supplier quotation extraction previously discarded the visual page/image payload generated by the shared document package before calling the supplier-reply AI extraction model. Text OCR could therefore be available while a scanned table, drawing, stamp or image-only quote was not shown to the model.

The correction:

- Carries transient `data:image/...` payloads from `processDocumentPackage()` into supplier AI documents.
- Deduplicates and caps supplier vision inputs at six images per extraction request.
- Uses `AI_VISION_MODEL` when configured, otherwise the existing `AI_MODEL`.
- Explicitly tells the model to inspect visual content as well as OCR text.
- Falls back once to text-only extraction when the provider explicitly rejects multimodal input; it does not retry this fallback for budget blocks or ordinary transient failures.
- Re-reads original stored attachments for an explicit owner-requested AI reprocessing operation so transient vision payloads can be regenerated without storing base64 images in the database.
- Adds unit coverage for image selection, forwarding and text-only fallback.

The extraction remains unverified and owner-reviewed. Deterministic RFQ matching is unchanged.

## Recommended build order for the remaining commercial lifecycle

1. **Sales order conversion** — on owner-confirmed customer PO/acceptance, create one idempotent sales order from the approved quotation version. Snapshot customer, currency, lines, quantities, prices, taxes, delivery/payment terms and source quotation. Detect and flag any PO-vs-quotation discrepancy; never auto-accept changed terms.
2. **Supplier purchase orders** — allow an owner to select approved supplier offers and create supplier-specific POs. Separate stock-sourced quantities from externally procured quantities. Require explicit owner approval before sending.
3. **Supplier commitments** — capture supplier acknowledgement, promised delivery, partial quantities, revised pricing and deviations against the PO.
4. **Goods receipt and fulfilment** — record partial/full receipts, inspection, quantity/quality discrepancies, inventory movements and customer dispatch/delivery evidence.
5. **Customer invoicing and payments** — create invoice records from confirmed delivered quantities, record receipts/allocations and outstanding balances. Do not claim payment is received without evidence or an integration event.
6. **Verified deal closure** — calculate open quantities, open supplier commitments, undelivered lines, unbilled value and unpaid balance. Allow close only when business-defined completion conditions are satisfied, with an audited override for exceptional cases.

Each stage needs tenant-scoped models, migrations, owner permissions, idempotent actions, audit records, durable background jobs where external calls are involved, and regression tests. Keep sales orders, supplier POs, invoices and payments as separate records; they are not interchangeable statuses on a quotation.
